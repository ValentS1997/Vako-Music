# Архитектура Vako Player 0.0.3

Одномодульное Android-приложение на Kotlin и Jetpack Compose. Минимальная версия Android — API 29, целевая и версия компиляции — API 34. Для видео используется Media3 ExoPlayer; аудио воспроизводится через Android `MediaPlayer` в фоновом `PlaybackService` с `MediaSession`.

## Основные части

| Компонент | Назначение |
| --- | --- |
| `MainActivity.kt` | Экраны Compose, навигация, локальная и удалённая медиатеки, очередь, темы и визуализация; фоновые операции выполняются в ограниченном пуле, закрываемом вместе с Activity. |
| `BackgroundTaskRunner.kt` | Постановка фоновых задач в ограниченный пул и уведомление владельца состояния при отказе executor. |
| `PlaybackService.kt` | Владелец аудиоплеера, MediaSession, Audio Focus и таймера сна; интерфейс отражает состояние сервиса. |
| `BatchOperations.kt` | Отчёт об успешных и неуспешных файловых операциях с возможностью повтора неуспешных. |
| `LibraryStore.kt`, `FolderIndex.kt`, `LibraryBrowse.kt` | Чтение локальной медиатеки, папки, группировка и плейлисты. |
| `MediaEdits.kt` | Изменение локальных аудиофайлов через Android MediaStore. |
| `VideoModule.kt`, `VideoStore.kt`, `VideoPlayerActivity.kt` | Видеомедиатека, просмотр и жесты. |
| `VideoPlaylistStore.kt`, `VideoHistoryStore.kt`, `VideoMediaManager.kt` | Видеоплейлисты, история и файловые операции. |
| `YandexMusic.kt`, `MusicRepository.kt`, `Http.kt` | Неофициальный клиент Яндекс Музыки и сетевые запросы; основа — [vladimir120307-droid/yandex-music-downloader](https://github.com/vladimir120307-droid/yandex-music-downloader). |
| `Downloader.kt`, `FlacRemux.kt`, `Id3.kt`, `Crypto.kt` | Потоковая загрузка и сохранение аудиофайлов, разбор контейнеров и запись тегов. |
| `TokenStore.kt` | Шифрование OAuth-токена ключом Android Keystore. |
| `ThemePalette.kt`, `AppPreferences.kt`, `SavedQueueStore.kt` | Тема, настройки модулей и сохранение очереди. |

Пакет приложения `ru.rikko.music` сохранён для совместимости с внутренними установками; отображаемое название — Vako Player.

## Данные и разрешения

- Локальные аудио и видео читаются через MediaStore после системного разрешения. Отдельный файл можно выбрать системным диалогом без полного доступа к медиатеке.
- Операции записи и удаления чужих медиафайлов требуют системного подтверждения Android. Действия с папкой касаются индексированных медиафайлов соответствующего типа.
- Очередь, плейлисты, настройки и история сохраняются в локальных `SharedPreferences`; OAuth-токен дополнительно шифруется через Android Keystore.
- Аудиовизуализация использует Android `Visualizer` и запрашивает `RECORD_AUDIO` при первом включении.
- Модуль Яндекс Музыки отправляет токен сервису в заголовке `Authorization`; см. [PRIVACY.md](PRIVACY.md).

## Технический долг

`MainActivity.kt` всё ещё объединяет много экранов и состояния; структурное разделение остаётся отдельной задачей. API Яндекс Музыки не документирован и требует контрактных проверок. Видео, фокус аудио и файловые операции необходимо шире испытать на Android разных производителей, накопителях и форматах. План проверок — в [SMOKE_TEST_MATRIX.md](SMOKE_TEST_MATRIX.md).
